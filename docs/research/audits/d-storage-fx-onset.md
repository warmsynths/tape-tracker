## 6. Things this got wrong or missed

Ordered by how much they change the plan.

1. **GlobalFileBrowser, SdPaths and every doc citing them do not exist in v1.0.0.** Section 5 of project-storage (reuse in "folder-package mode", `contextKey`, `onDescribeItem`, `confirmOverwrite`, 32 recents, 1..60 name clamp) is wrong. Real v1.0.0 mechanism: `FileBrowser` plus the Open/Save As code in `fProjEdit.cpp`. The recommendation (own folder and own marker file) still works but needs two small hard-coded `project.mt` strings changed (PS19), and it inherits stock's 256-entries-per-folder cap and 32-char keyboard cap.
2. **A first-sound detector already ships.** `calculateStartPointFromRecording` / `calculateEndPointFromRecording` (OD15) run after every Sample Recorder take. The onset doc and readiness row 1 should start from it (fixed -70 dBFS threshold is its weakness).
3. **A click source already ships** (`makeMetronomeTick`, TK8). Readiness rows 3 and 21 ("needs a click sound source", firmware path Unknown) are wrong.
4. **The limiter already has a gain-reduction readout** (MF9), so rows 11 and 25 are buildable on a known path.
5. **PROJECT_FILE_VERSION is 17, not 18, and `strMtValues` has no size static_assert in v1.0.0** (PS9, PS10). The "frozen, size-asserted struct" argument against reusing `project.mt` is weaker than stated: the only enforcement is the repo rule in `CONTRIBUTING.md:59` plus the runtime size check that resets the name to "Unsaved Project" (`fileManagerProject.cpp:89-98`). Also about 800 bytes of pattern-editor fields in `strMtValues` are dead for our UI (PS16).
6. **"No compressor"** is only true for a dedicated master compressor. v1.0.0 also has: (a) `AudioEffectDynamics`, a real compressor with soft knee, ratio to 60:1 and auto makeup, one mono instance per input channel, already compiled and running at defaults (MF10-MF15); (b) the SGTL5000 codec's **auto volume control**, which has an explicit `compressor` / `hardLimiter` mode, threshold -96..0 dB, attack and decay, 0/25/50/100 ms response (`mtAutoVolumeControl.h:7-47`, driver `platforms/mk66/3rdparty/Audio/control_sgtl5000.cpp:955-975`, impl `Sgtl5000Impl.cpp:45-64`). It runs in the codec's processor, which `enableHardwareProcessor(true)` already puts after the MCU output (`control_sgtl5000.cpp:851-855`, `mtAudioEngine.cpp:271`), so it costs no MCU time and sits after our limiter. **Warning, it is unused and the driver has bugs:** threshold, attack and decay are computed into `uint8_t` (`control_sgtl5000.cpp:964-966`, values up to 2^19 truncated), and `Sgtl5000Impl::configureAutoVolume` passes `maxExpanderGainType` twice and drops `responseTimeType` (`Sgtl5000Impl.cpp:57-62`). It would need fixing and ear-testing. (c) the master limiter with slow release and a low threshold, with a keyed sidechain.
7. **"Wow/flutter must be written"** is true for the master bus only. Per-voice pitch LFO exists (MF28). The codec also has a 7-band parametric EQ driver (`control_sgtl5000.cpp:909+`, `eqFilter`) beyond the 5-band graphic EQ used today (`Sgtl5000Impl.cpp:81-91`); not wired in the UI.
8. **Master-bus bounce/capture exists as plumbing:** a record queue on `finalMixer` (the master) and on each voice (RM16), the exporter's chunked raw-to-WAV converter (`mtAudioExport.cpp:452-560`), and a codec routing that returns processed audio to the MCU (`audioPostProcessorAndExportEnable`, `control_sgtl5000.cpp:856-859`, unused). Not needed for v1 (no bounce) but it answers "is there a resample/bounce mechanism".
9. **Stock WAV export is sequencer-driven** (RM15). Our export of N loop repeats should copy `exportProjectSamples`' chunked header-first writer instead (`fileManagerExport.cpp:~395-445`), not the sequencer exporter.
10. **No project rename in v1.0.0** (RM14a). "Save your changes?" before New/Open already exists, so feature 23 is cheaper than the matrix says.
11. **Device settings can use `strCommonValues`** (append at the end) with no new section and no change to `mtConfig.cpp` lists (RM13).
12. Wrong or missing on the plugin side: bundled `.ptfx` list and scratch size (MF26); `docs/memory_map.md` numbers (MF4). The stale `core/build-MK66-ORIGINAL` objects are from unreleased main and should not be used as evidence of what v1.0.0 compiles; this audit read only source.
13. Smaller: stock keyboard accepts only FAT-safe characters (PS26), `Recorder` has no pre-roll (OD18), CMSIS-DSP is linked on MK66 (OD17), the `/.develop` profiler is real but undocumented in `developer_guide.md` (MF6).
